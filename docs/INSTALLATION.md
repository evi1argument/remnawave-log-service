# Установка Remnawave Log Service

Это инструкция для новой установки **v1.3.0**. Мастер из [быстрого старта](../README.ru.md#мастер-установки) настраивает отдельный коллектор с локальным архивом. Ручная установка ниже подходит для S3, Google Drive и коллектора, который одновременно работает как VPN-нода. [Обновление действующей установки](UPGRADING.md)

Нужны Debian или Ubuntu с systemd, доступ root, IPv4 и [Docker Engine 28+ с плагином Compose](https://docs.docker.com/engine/install/). На коллекторе Docker должен использовать iptables. До запуска контейнеров ограничьте входящий TCP/6000 адресами нод в межсетевом экране провайдера или используйте закрытую сеть.

<a id="prepare-xray"></a>
## Подготовьте логи Xray на каждой ноде

1. Создайте каталог `/var/log/remnanode` на сервере ноды. В Compose-файле вашей Remnawave-ноды добавьте в `volumes` сервиса `remnanode` этот каталог.

   ```yaml
   volumes:
     - /var/log/remnanode:/var/log/remnanode
   ```

2. В панели Remnawave откройте профиль конфигурации Xray, который использует нода. Добавьте или обновите блок `log`, сохранив остальную конфигурацию.

   ```json
   {
     "log": {
       "access": "/var/log/remnanode/access.log",
       "error": "/var/log/remnanode/error.log",
       "loglevel": "warning"
     }
   }
   ```

3. Примените изменения Compose и профиля на ноде. Проверьте на хосте, что появился `/var/log/remnanode/access.log`. Установщик агента проверяет наличие файла. Настройте ротацию с `copytruncate`, чтобы логи не заполнили диск. Установщик может добавить [конфигурацию ротации из репозитория](../node/logrotate-remnanode), если на ноде есть logrotate и файла `/etc/logrotate.d/remnanode` ещё нет. [Руководство Remnawave по логам нод](https://github.com/remnawave/panel/blob/main/docs/install/remnawave-node.md#node-logs)

## 1. Установите коллектор

Выберите, где хранить архив. В Loki последние 30 дней доступны для поиска независимо от выбранного архива.

| Хранилище | Что подготовить |
| --- | --- |
| Локальный диск (`local`) | Каталог и срок хранения архива. Путь по умолчанию — `/opt/logcollector/archive/store`. |
| S3 (`s3`) | Бакет, регион, HTTPS-эндпоинт и отдельный ключ с правами на этот бакет. Для защиты от удаления проверьте поддержку Object Lock и версионирования у провайдера. |
| Google Drive (`gdrive`) | Настройте `rclone config` под root, чтобы служба архива могла использовать подключение. Подготовьте путь вида `remote:path`. |

Для облачного архива выбирайте `ENCRYPT=age`. На коллектор передайте открытый ключ age. Закрытый ключ нужен для восстановления, храните его отдельно.

Выполните на коллекторе от root.

```bash
git clone --branch v1.3.0 https://github.com/evi1argument/remnawave-log-service.git
cd remnawave-log-service/collector
./install-collector.sh
```

Установщик спросит тип хранилища, параметры шифрования и частоту архивации. Для отдельного коллектора укажите `COLLECTOR_NODE=-`. Если адрес для подключения нод отличается от предложенного, задайте `COLLECTOR_ADDRESS` при запуске. При распаковке ZIP запускайте `bash install-collector.sh`.

Для S3 можно запустить `APPLY_COMPLIANCE=yes ./install-collector.sh`. Сначала убедитесь, что бакет поддерживает Object Lock и вам подходит заданный скриптом режим Compliance на 180 дней.

## 2. Установите агент на каждой ноде

Замените `COLLECTOR` адресом коллектора, доступным с ноды, а `NODE_NAME` уникальной меткой ноды, например `demo-north`. Перед копированием открытого TLS-сертификата проверьте ключ SSH-хоста коллектора.

```bash
git clone --branch v1.3.0 https://github.com/evi1argument/remnawave-log-service.git
cd remnawave-log-service/node
scp root@COLLECTOR:/opt/logcollector/vector/tls/cert.pem ./collector.crt
COLLECTOR_CERT=./collector.crt COLLECTOR_IP=COLLECTOR ./install-node.sh NODE_NAME
```

На коллекторе замените `NODE_IP` адресом, с которого приходит соединение. Если нода за NAT, используйте её внешний IPv4. Разрешите тот же адрес в межсетевом экране провайдера.

```bash
/opt/logcollector/scripts/collector-add-node-fw.sh NODE_IP
```

Установщик настраивает ограничение доступа в цепочке Docker `DOCKER-USER` и восстанавливает правила через systemd. Для опубликованного контейнером TCP/6000 настройка UFW сама по себе не ограничивает входящие подключения. [Как Docker взаимодействует с UFW](https://docs.docker.com/engine/network/packet-filtering-firewalls/#docker-and-ufw)

## 3. Найдите первую запись в Grafana

На своём компьютере откройте SSH-туннель. Замените `COLLECTOR` адресом коллектора.

```bash
ssh -N -L 3000:127.0.0.1:3000 root@COLLECTOR
```

Откройте `http://127.0.0.1:3000` и войдите как `admin`. Пароль хранится в `/opt/logcollector/.env` на коллекторе. Откройте **Remnawave Logs → Log search**, выберите ноду и найдите недавнюю запись. Если записей нет, проверьте, что Xray пишет в файл на ноде и что коллектор разрешает её IPv4. В мастере можно выбрать **Проверить сервер** или запустить `sudo bash install.sh --lang ru doctor`.

## После установки

- [Доставка логов](LOG-DELIVERY.md) — контрольная запись раз в минуту для каждой включённой ноды.
- [Telegram](TELEGRAM.md) — правило Grafana на всплески строк в `error.log`.
- [Отчёты и поиск аккаунтов](../report/README.md) — поиск по IP, домену или ID и отдельный поиск аккаунта на сервере панели.

Настройки архива лежат в `/opt/logcollector/archive/archive.conf`. Таймер `archive-upload.timer` запускает архивацию раз в час, день или неделю. Мастер по умолчанию выбирает ежедневный запуск, ручной установщик — еженедельный. Архиватор обрабатывает файлы после минимального срока ожидания `SETTLED_MIN` (65 минут по умолчанию) и пропускает файлы, которые ещё открыты на запись. Чтобы проверить запуск на коллекторе, выполните от root.

```bash
systemctl start archive-upload.service
journalctl -u archive-upload.service -n 20
```

Для выгрузки локального архива по SSH используйте `scripts/pull-to-pc.sh` из репозитория. При более редкой архивации больше записей остаётся только в Loki и очереди на диске коллектора.

## Доступ к логам

В записях Xray могут быть IP-адреса клиентов, адреса назначения и числовые идентификаторы аккаунтов. Сопоставление ID с аккаунтом выполняйте на сервере панели. Ограничьте доступ к Grafana и архивам, настройте сроки хранения.

Агент проверяет сертификат и TLS-имя `logcollector`. До окончания срока действия сертификата обновите доверенную копию на каждой ноде. Коллектор ограничивает отправителей списком IPv4-адресов. TLS проверяет подлинность коллектора и шифрует соединение. Отдельная аутентификация агентов в этой конфигурации отсутствует. [Обновление и ограничения](UPGRADING.md)
