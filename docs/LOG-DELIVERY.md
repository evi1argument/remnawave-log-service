# Проверка доставки логов

На ноде можно включить таймер, который раз в минуту пишет строку с Unix-временем в `/var/log/remnanode/log-service-canary.log`. Vector отправляет её по тому же TLS-транспорту, что и Xray-логи. Коллектор кладёт запись в отдельный поток Loki `{service="log-service",stream="canary"}` с исходным временем. Даже при повторной доставке старая запись не будет считаться свежей. Контрольные записи не попадают в raw spool, архив и запросы к `service="xray"`.

## Порядок включения

1. Обновите конфигурацию Vector на коллекторе, затем на выбранной ноде. При обновлении существующей установки сохраните её параметры, сертификаты и тома Vector. Проверьте конфигурацию и пересоздайте только контейнеры Vector с обновлёнными файлами привязки. Старый агент продолжит отправлять обычные логи новому коллектору. Старый коллектор отбросит контрольные записи нового агента.
2. Убедитесь, что на ноде синхронизированы часы и logrotate ротирует `/var/log/remnanode/log-service-canary.log`. Штатный `node/logrotate-remnanode` включает его через `*.log`. Если коллектор одновременно VPN-нода, таймер можно запустить и на нём.
3. Из корня репозитория скопируйте юниты на выбранной машине и включите таймер:

```sh
sudo install -m 0644 node/systemd/log-service-canary.service node/systemd/log-service-canary.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now log-service-canary.timer
sudo systemctl start log-service-canary.service
```

4. В Explore или внешнем мониторинге выполните мгновенный запрос:

```logql
sum by (node) (count_over_time({service="log-service",stream="canary"}[5m]))
```

Сравните результат с явным списком ожидаемых меток нод. Если запрос успешен, а метка отсутствует, проверьте таймер ноды, её Vector, транспорт и приём на коллекторе. Ошибка самого запроса требует отдельного сигнала. Добавляйте ноду в список ожидаемых после появления её свежих записей.

Контрольная запись проверяет путь из каталога логов через Vector в Loki. Для проверки Xray и архива нужны отдельные сигналы. При отказе всего коллектора оповещение должен отправить внешний мониторинг.

Для отключения сначала уберите ноду из списка ожидаемых в мониторинге, затем выполните `sudo systemctl disable --now log-service-canary.timer`. При повторном включении дождитесь новой записи перед возвратом ноды в список.
