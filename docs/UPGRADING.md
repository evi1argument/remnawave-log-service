# Обновление и надёжность

## С v1.1.0 на v1.2.0

Для этого перехода достаточно обновить конфигурацию Vector. В штатной установке на коллекторе она лежит в `/opt/logcollector/vector/vector.aggregator.yaml`, а на ноде — в `/opt/logship/vector.yaml`.

1. Сохраните действующую конфигурацию Vector. Сравните её с шаблоном из v1.2.0 и перенесите изменения, сохранив метки нод, адрес коллектора, TLS и локальные настройки. На выделенном коллекторе без VPN-ноды оставьте только удалённые источники, как при `COLLECTOR_NODE=-`. В шаблоне агента имя и адрес задаются вместо `__NODE_NAME__` и `__COLLECTOR_IP__`.
2. Из каталога действующего Compose проверьте новый файл до его установки. Подставьте абсолютный путь к подготовленной конфигурации:

   ```bash
   docker compose run --rm --no-deps --volume /vector-data \
     --volume /absolute/path/to/candidate.yaml:/etc/vector/vector.yaml:ro \
     vector validate --skip-healthchecks /etc/vector/vector.yaml
   ```

3. Сначала замените файл конфигурации коллектора и выполните `docker compose up -d --no-deps --force-recreate vector` в `/opt/logcollector`. Проверьте появление свежих Xray-логов в Loki и spool. Затем повторите на одной ноде из `/opt/logship`. При успешной проверке обновите остальные ноды. Сохраните существующие тома и сертификаты.
4. [Включайте контрольные записи](LOG-DELIVERY.md) по одной ноде после обновления её агента. Перед добавлением ноды в список внешнего мониторинга дождитесь свежей записи в Loki.

Для отката исключите ноды из списка мониторинга и остановите таймеры контрольных записей. Восстановите сохранённую конфигурацию Vector и пересоздайте только его контейнеры. При откате всего обновления сначала верните конфигурации агентов, затем коллектора.

## Общие требования

В Compose закреплены Vector **0.61.0**, Loki **3.7.10**, Grafana **13.3.1**.
Это обновление исходников; загрузка репозитория сама по себе не меняет рабочие контейнеры.

- Дисковые буферы по 512 МиБ на отправку агента и на каждый из двух выходов коллектора,
  `when_full: block` и подтверждения доставки. Нужен запас места: до 512 МиБ на ноде,
  до 1 ГиБ на коллекторе **дополнительно к Loki и spool**. Сам том должен вмещать эти лимиты.
- Архиватор блокирует параллельный запуск через `flock`. Ошибки загрузки, шифрования,
  чтения spool и retention возвращают ненулевой код; опечатка в `ENCRYPT` не включает plaintext.
- Старый сегмент атомарно перемещается в `spool/.archive-pending/`. Если Vector ещё держит
  его inode открытым, `fuser` откладывает загрузку до следующего запуска. Ошибка оставляет
  сегмент в очереди. Новые строки по исходному пути не удаляются вместе со старым сегментом.
- Ключ нового объекта: `raw/<node>/<YYYY/MM/DD>/<HH>.segment.<id>.<sha256>.log[.age]`.
  Разные сегменты одного часа, даже с одинаковыми байтами, не заменяют друг друга.
  Старые ключи остаются читаемыми; SHA-256 относится к исходным байтам до шифрования.
- `age` работает во временном каталоге с правами 0700; локальная публикация — через
  временный файл и rename. Незавершённая загрузка не считается готовым локальным архивом.
- Повторная установка сохраняет TLS-пару; неполная пара останавливает установку.
  Firewall должен успешно примениться до публикации приёмника. Vector проверяется до запуска.
- Перенесены локальные исправления: Remnawave 2.x/3.x (`users.t_id`/`users.id`) и
  `COLLECTOR_NODE=-` для отдельного коллектора без локальной VPN-ноды.

### Проверки и обновление существующей установки

Архиватор запускается **на Linux-хосте от root**, с видимым host `/proc`, `CAP_SYS_PTRACE`
и без AppArmor/SELinux-профиля, скрывающего чужие файловые дескрипторы. В ограниченном
контейнере проверка открытого файла ненадёжна; архиватор откажется работать при обнаруженном
ограничении. Нужны `psmisc` (`fuser`) и `util-linux` (`flock`); инсталлятор ставит их.

Перед изменением рабочего стека:

1. Сохранить Compose, `.env`, `archive.conf`, S3/rclone-настройки, public age key,
   TLS-пару, firewall allow-list и Grafana/Loki volumes. Snapshot БД Grafana делать
   согласованно с остановкой Grafana или штатным SQLite backup. Для обновления Grafana
   11 → 13 заранее изучить breaking changes промежуточных версий; тест на пустой БД
   не подтверждает миграцию существующей БД, плагинов и пользовательских дашбордов.
2. Запустить в клоне `bash scripts/check-configs.sh`, затем `sudo python3 tests/smoke_stack.py`.
   Проверки не публикуют порты и используют только временные данные. Smoke требует
   Linux Docker и доступа хоста к IP контейнеров внутренней bridge-сети.
3. На коллекторе установить зависимости: `apt-get install -y psmisc util-linux`.
   Переносить настройки из существующей установки осознанно: инсталлятор генерирует
   `archive.conf` и `.env` заново. Не запускать его как универсальный updater без backup.
4. Сохранить целиком `spool`, включая `.archive-pending`; не чистить очередь при
   ошибках. Сначала обновлять коллектор, затем агентов, проверяя появление свежих логов.
   Проверить ручной запуск `archive-upload.service` и чтение пробного объекта из архива.
5. При откате Grafana восстановить **и старый образ, и согласованную копию её БД**.
   Старый архиватор не знает об очереди `.archive-pending`: её нужно сохранить и
   обработать новым архиватором, прежде чем возвращаться к старой реализации.

CI запускает синтаксические проверки Bash, регрессионные тесты архиватора,
валидацию Vector/Loki и полный smoke: TLS-агент + локальный источник → Loki + raw spool,
затем health Grafana, два provisioned-дашборда и datasource Loki.
Локальный запуск регрессий на тестовом Linux-хосте:
`sudo python3 -m unittest discover -s tests -v` (нужны `psmisc` и `age`).

### Что показало изучение upstream

- [Vector: buffering model](https://vector.dev/docs/architecture/buffering-model/) —
  дисковые буферы и backpressure уменьшают потери при сбоях, но конечный диск может заполниться.
- [Vector: file sink](https://vector.dev/docs/reference/configuration/sinks/file/) —
  file sink **не делает fsync на каждое подтверждение**. Подтверждение не означает,
  что данные уже в удалённом архиве. Полное отсутствие потерь при гибели диска не гарантируется.
- [Loki: cardinality](https://grafana.com/docs/loki/latest/get-started/labels/cardinality/) —
  метки `node/service/stream` сохраняем; IP, домены и user ID не переносим в индексные метки.
- [Grafana CVE-2025-4123](https://grafana.com/security/security-advisories/cve-2025-4123/) —
  прежняя 11.4.0 предшествует исправлению этой XSS. Доступ Grafana остаётся через loopback/SSH.
- Подтверждённые релизы: [Vector 0.61.0](https://github.com/vectordotdev/vector/releases/tag/v0.61.0),
  [Loki 3.7.10](https://github.com/grafana/loki/releases/tag/v3.7.10),
  [Grafana 13.3.1](https://github.com/grafana/grafana/releases/tag/v13.3.1).

Перед обновлением агентов скопируйте на них публичный `cert.pem` коллектора
через доверенный SSH. Проверьте имя сертификата (`logcollector`) и срок действия.
Старые сертификаты без SAN могут потребовать перевыпуска; спланируйте замену пары
на коллекторе и копий на нодах, сохранив резервную копию. Старый агент продолжает
передавать данные без проверки сервера до обновления его конфигурации.

Отдельно остаются mTLS для идентификации агентов и оповещения по буферам,
свободному месту и возрасту очереди архива.
Время жизни raw spool зависит от каденции; открытый сегмент может ждать ещё один цикл.
Повторы после неоднозначного ответа облака могут создать дополнительные версии объекта;
это доставка с возможными повторами, а не exactly-once.

[VictoriaLogs](https://docs.victoriametrics.com/victorialogs/keyconcepts/) интересен
полнотекстовым индексом всех полей, но его внедрение потребует переписать запросы LogQL,
CLI-отчёты и дашборды. Пока нет измерений узкого места Loki на нашем объёме,
такой переход не обоснован. Для следующего этапа полезнее
[internal_metrics Vector](https://vector.dev/docs/administration/monitoring/):
ошибки компонентов, заполнение буферов и отбрасываемые события.
