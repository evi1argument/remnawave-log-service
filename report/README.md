# Поиск подключений по IP, домену и ID пользователя

Соберите записи о подключениях на коллекторе. Если нужно узнать, какому аккаунту принадлежит числовой ID из журнала Xray, проверьте его на сервере панели, где хранится база аккаунтов.

## Найдите записи на коллекторе

Установщик копирует команду в `/opt/logcollector/report/investigate.sh`.
```bash
investigate.sh --from <t> [--to <t>] [--user <t_id>] [--ip <addr>] [--domain <re>] [--node <re>] [--out chain.tsv]
```
Для `--from` и `--to` укажите время в формате RFC 3339 (`2026-01-10T00:00:00Z`) или относительно текущего момента (`-24h`, `-7d`, `now`).
Отчёт содержит поля `timestamp_utc`, `node`, `client_ip`, `t_id`, `proto`, `dest`, `dport` и `outbound`. В конце выводится список ID и команда для поиска аккаунтов.

Примеры:
```bash
investigate.sh --from -24h --ip 203.0.113.7
investigate.sh --from 2026-01-10T00:00:00Z --to 2026-01-11T00:00:00Z --user 42 --out u42.tsv
investigate.sh --from -7d --domain 'example\.com' --node node1
```
Loki по умолчанию хранит 30 дней. Для более раннего периода возьмите файлы из архива. Для расшифровки файлов `.age` понадобится закрытый ключ.

## Найдите аккаунт на сервере панели

Скопируйте скрипт из корня репозитория на сервер панели по SSH. Замените `PANEL` адресом панели.

```bash
scp report/resolve-users.sh root@PANEL:/root/resolve-users.sh
```

На сервере панели выполните команду с нужными ID.
```bash
bash /root/resolve-users.sh <t_id> [t_id ...]
```
Скрипт выдаёт имя пользователя, Telegram ID, email, описание, статус и срок действия аккаунта. Для нестандартной установки задайте `PANEL_DB_CONTAINER`, `PG_USER` и `PG_DB`.

> Соответствие: xray в access-логе пишет `email: N`, где `N` — числовой PK пользователя панели.
> **Имя колонки зависит от версии панели:** до 3.0.0 это `users.t_id`, начиная с 3.0.0 —
> `users.id` (миграция `20260720124815_rename_column`; заодно там же удалён `users.uuid`).
> Значения при переименовании сохранились, так что старые `t_id` из архивных логов остаются
> валидными. Скрипт определяет имя колонки сам через `information_schema` и работает на обеих
> версиях — правки при апгрейде не требуются.
